# T026 観察者ガイドライン & 無誘導進行要領 (Observer Guide)

## 1. 基本態度と行動規範

観察者（テスト実施者）の最も重要な役割は、**「ユーザーに解法や操作手順を教えず、自力での操作行動を客観的に記録すること」** です。

開発者が良かれと思って助言をすると、サイト本来の UX 欠陥が見えなくなり、テストの検証価値が損なわれます。以下の規範を厳守してください。

---

## 2. セッション開始時の口頭説明スクリプト

セッション開始時、テスターに伝える説明は以下のみとします。

> **【定型案内文】**
> 「本日はテストにご協力いただきありがとうございます。
> これは世界のニュースを見るための Web サイトです。これからいくつかの課題をお願いします。
> サイトの操作方法は説明しませんので、普段 Web サイトを使う感覚で自由に操作してください。
> 分からないときは、遠慮なく『分からない』と言ってください。
> あなたの操作の正解・不正解を試すのではなく、このサイトが使いやすいかどうかを確認しています。」

---

## 3. ユーザーから「助けて」「分からない」と言われた場合の対応

ユーザーが操作に迷ったり助言を求めてきた場合、すぐに答えを教えてはいけません。以下のステップで対応してください。

### ステップ 1 (初期応答)
まず逆質問をして考えを引き出します。
- 「どうしたらできると思いますか？」
- 「今、何をしようとしていますか？」
- 「どの部分を見てそう思われましたか？」

### ステップ 2 (支援レベルの分類と記録)
やむを得ず支援を提供した場合は、以下の **Help Level** として正確に記録します。

| Help Level | 支援内容 | 記録例 |
|---|---|---|
| **Level 0 (なし)** | 自力で達成、または助言なし | 完全成功または自力解決 |
| **Level 1 (逆質問)** | 「何を探していますか？」等の質問返しで気づいた | ヒントなしの気づき |
| **Level 2 (領域指示)** | 「画面の上の方を見てみてください」等、大まかな位置を提示 | 領域指図 |
| **Level 3 (操作教示)** | 「このボタンを押してください」と直接操作手順を指示 | 完全教示（部分成功/失敗扱い） |

---

## 4. Think Aloud (思考発話) の案内

ユーザーに思考の言語化を促します。負担を感じている場合は無理に強制しません。

> 「操作中、『どこを見ているか』『次何をしようとしているか』を声に出しながら操作していただけると助かります。」

---

## 5. 観察・記録項目仕様

各タスク (UJ-001〜UJ-016) ごとに以下の項目を記録シートに記入します。

* **Task ID**: タスク番号 (例: UJ-005)
* **Tester ID**: テスター番号 (`T01`, `T02`, `T03`)
* **Success**: 成功 (`Yes`), 部分成功 (`Partial`), 失敗 (`No`), 重大失敗 (`Critical`)
* **Time (sec)**: タスク文を読み終えてから目的達成（または諦め）までの所要秒数
* **Error Count**: 誤クリック、無関係なページへの遷移、誤ったフィルター適用回数
* **Help Level**: `0` 〜 `3`
* **Confusion Level**: 迷い・戸惑いの度合い (`0`: なし 〜 `3`: 強い困惑)
* **Confidence Level**: 自信の度合い (`1`: 全く自信なし 〜 `5`: 確信がある)
* **Observation / Comment**: ユーザーの具体発言、目線の動き、迷ったUI要素
